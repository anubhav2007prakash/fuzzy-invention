# SentinelCrypt AI — Demo Script & Professor Discussion Sheet

## Five-Minute Demo
**0:00–0:40:** Explain the problem: IDS trust involves more than classification accuracy.

**0:40–1:30:** Show architecture: dataset → ML → prediction → XAI → cryptographic ledger.

**1:30–2:30:** Make a controlled prediction and show class, confidence where supported, and explanation.

**2:30–3:20:** Verify a valid local ledger, mutate one test record, verify again, and show detection.

**3:20–4:20:** Show one model-comparison, generalization, or explanation-stability result.

**4:20–5:00:** State limitations and threat-model assumptions.

## Professor Questions
- Is the explanation-stability metric appropriate for this feature space?
- Would temporal validation improve the study?
- Which additional baseline is necessary?
- How should cross-dataset feature mapping be controlled?
- What stronger authenticity mechanism could be explored later?
- Which component is suitable for supervised research?

## Short Introduction
“I’m building SentinelCrypt AI, a research-oriented intrusion-detection prototype combining ML classification, explainable AI, and a cryptographic hash-linked audit ledger. I’m studying not only prediction performance, but also explanation stability and whether stored alert evidence can be checked for tampering. I’d especially value feedback on the experimental methodology and how the prototype could develop into a rigorous research study.”
